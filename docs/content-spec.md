# CCNAクエスト コンテンツ仕様

対象試験: **Cisco CCNA 200-301 v1.1**(受験は2026年11月後半〜12月上旬)。
読み手: 勉強が苦手で、ネットワークの知識がほぼゼロの社会人。やさしく、でも試験に出るポイントは外さない。

## 1. 1エリア = 1つのJSファイル

`packs/ccna/<エリアid>.js` に、次の形で1つだけエリアを登録する。

```js
QUEST.addArea('ccna', {
  id: 'a1',                       // 担当エリアのid(指示されたもの)
  order: 1,
  name: 'はじまりの森',            // 指示されたもの
  domain: 'Network Fundamentals', // 公式の出題分野名
  objectives: '1.1-1.5, 1.11',    // 対応する公式試験項目の番号
  teacher: {
    name: 'ハカセ',
    pages: [                      // 3〜5ページ。1ページ80字以内。たとえ話中心の導入
      '…',
    ],
  },
  monsters: [
    {
      id: 'a1-router',            // 'エリアid-英小文字とハイフン'。全体で重複禁止
      nick: 'ルーたん',            // 覚えやすいオリジナルのあだ名(3〜6文字)
      term: 'ルーター (Router)',   // 本物の用語。英語表記を必ず併記
      tier: 1,                    // 難しさ 1(やさしい)〜3(難しい)
      analogy: '…',               // 身近なたとえ話 1〜2文(80字以内)
      points: ['…', '…'],         // 試験で問われる要点 2〜3個(各40字以内)
      questions: [                // 3〜4問
        {
          q: '…',                 // 問題文(1〜2文、80字以内。\n で改行可)
          choices: ['…', '…', '…', '…'],  // 必ず4択。各30字以内
          a: 0,                   // 正解の番号(0〜3)。位置は偏らせない(0〜3を均等に)
          ex: '…',                // 解説 1〜3文。なぜ正解か+紛らわしい誤答がなぜ違うか
        },
      ],
    },
  ],
});
```

## 2. 数

- モンスター(=覚える用語/概念): **12〜15体**
- 1体あたりの問題: **3〜4問**(同じ概念を別の角度から。言い換えるだけの水増しは禁止)
- 先頭の1〜2体は tier 1(入門)、最後の方に tier 3(応用)を置いて、学ぶ順に並べる

## 3. 書き方のルール(最重要)

1. **たとえ話が先、専門用語があと。** `analogy` は日常のもの(郵便、学校、会社、道路、レストラン等)で説明する。
2. **正確さ最優先。** CCNA 200-301 v1.1 の公式試験範囲に沿い、確かな事実だけを書く。自信がない数値・仕様は書かない(問題にもしない)。バージョン依存や機種依存の細かい話は避ける。
3. **オリジナルで書く。** Ciscoの公式問題、問題集(ダンプ)、書籍、他サイトの文章を写さない。自分の言葉で作る。
4. 専門用語は **英語の正式名称を併記**(試験は英語/日本語の併用で、英語用語を覚える必要があるため)。略語は初出で正式名称を示す。
5. 問題文は短く。スマホ画面で読める長さ。選択肢も短く。「すべて正しい」「どれも違う」は使わない。
6. 誤答の選択肢は「紛らわしいが明確に間違い」にする(ひっかけすぎ・揚げ足取りは禁止)。正解が1つに定まること。
7. 解説は**やさしい言葉**で、なぜその答えかを説明する。責める調子は使わない。
8. 試験に出るコマンドや設定は、`show ip route` のようにそのまま書いてよい。
9. ニックネーム(`nick`)はオリジナル。既存のゲームやアニメのキャラ名・技名を使わない。
10. JSの文字列は ' ' で囲み、中に ' を使うときは \' にする(または " " で囲む)。構文エラーは致命的なので、書き終えたら必ず読み直す。

| a2 | アドレスの町 | Network Fundamentals (IPアドレス編) | 1.6 IPv4とサブネット / 1.7 プライベートIPv4 / 1.8 IPv6 / 1.9 クライアントのIP設定確認 / 1.10 無線の基本(チャネル、SSID、周波数帯) |
| a3 | スイッチの谷 | Network Access (20%) | 2.1 VLAN / 2.2 トランク・802.1Q / 2.3 L2ディスカバリ(CDP, LLDP) / 2.4 EtherChannel(LACP) / 2.5 RSTP / 2.6 無線アーキテクチャ(AP, WLC) / 2.7 物理インフラ接続 / 2.8 無線管理 |
| a4 | ルートの街道 | IP Connectivity (25%) | 3.1 ルーティングテーブルの構成要素 / 3.2 ルート選択(最長一致, AD, メトリック) / 3.3 スタティックルート / 3.4 OSPFv2 シングルエリア / 3.5 FHRP の目的 |

| a6 | セキュリティの砦 | Security Fundamentals (15%) | 5.1 脅威・脆弱性・攻撃 / 5.2 セキュリティ対策 / 5.3 パスワードポリシー・MFA / 5.4 IPsec VPN の概念 / 5.5 ACL / 5.6 L2セキュリティ(ポートセキュリティ, DHCPスヌーピング, DAI) / 5.7 AAA / 5.8 WPA/WPA2/WPA3 / 5.9 無線LANのセキュリティ設定 |

## 5. 完成したら

- ファイルを保存し、エリアの冒頭に書いたルールを自分で守れているか読み返す。
- 報告は短く: モンスター数・総問題数・自信のない箇所(あれば)のみ。
